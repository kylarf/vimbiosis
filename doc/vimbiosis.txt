*vimbiosis.txt*  Vim and coding agent integration

VIMBIOSIS                                                *vimbiosis*

Install this repository at pack/vendor/start/vimbiosis. Add its bin directory
to PATH for external agent processes. The :Vbio command sets PATH for agent
terminals it starts.

COMMANDS                                                *vimbiosis-commands*

:Vbio {codex|claude} [arguments]  Start an agent in a terminal split.
:VbioAttach                       Attach the current Vim to an external agent.
:VbioStatus                       Show bridge status.
:VbioDetach                       Stop the bridge and detach.
:VbioFollow                       Toggle automatic file following.
:VbioChanges                      Open the change location list.
:VbioDiff                         Review the current file in a native diff tab.
:VbioToggleChanges                Toggle the agent change location list.
:VbioNext                         Jump to the next changed region.
:VbioPrevious                     Jump to the previous changed region.
:VbioClear                        Clear this buffer's change markers.
:VbioChangesClear                 Clear the change list and all its markers.

After :VbioAttach, evaluate the printed export command in the external
agent's shell. The variable must be inherited when the agent starts.

The bridge requires Python 3 available as python3. It listens on an OS-assigned
TCP port bound only to 127.0.0.1 and authenticates requests using a random
per-session token. VIMBIOSIS_SESSION contains <port>:<token>. Startup waits up
to five seconds for the bridge to publish this descriptor before launching an
agent or printing an attachment command. The bridge exits when Vim closes its
input channel, and Vim clears the session when the bridge exits or detaches.

The TCP transport is shared across macOS, Linux, and Windows. On Windows, run
Vim from Git Bash with python3 and the agent commands on PATH. The Bash entry
point and launch commands are unchanged; Windows launch validation is pending.
After upgrading from the Unix-socket bridge, use :VbioDetach and start a new
attachment. Export the new descriptor and restart external agents.

CLI                                                     *vimbiosis-cli*

vimbiosis status
vimbiosis buffers
vimbiosis read-buffer FILE [--start N --end M]
vimbiosis open FILE [--line N --column N --vertical]
vimbiosis notify FILE...

Buffer reads return live contents, including unsaved edits.

CHANGE REVIEW                                           *vimbiosis-changes*

Configure both PreToolUse and PostToolUse hooks using codex/INSTALL.md or
claude/INSTALL.md. The pre-edit hook blocks direct edits to unsaved buffers,
returning feedback that asks the agent to wait for your decision. Resolve
the buffer in Vim before retrying. Checks cover the configured direct edit
tools; shell commands and external writers are not intercepted.

Successful pre-edit checks capture a before snapshot. After the tool finishes,
the viewer highlights added lines with VimbiosisAdded (linked to DiffAdd),
replacements as deleted original lines using VimbiosisDeleted (DiffDelete)
followed by added lines using VimbiosisAdded. Deletions also use a virtual
display of removed original lines.
By default, added lines and replacement text have an inline "+" marker.
Removed lines wrap and use "-" by default. Markers are always prepended without
an extra space, preserving the original indentation. Removed lines appear above
the next surviving line (below the last line for end-of-file removals). Empty files
use their empty first line as the anchor. Buffer text and modified state are
unchanged. This requires +textprop and Vim patch 9.0.0438 or newer.
Virtual-text mode uses addition/removal colors and does not open a sign gutter.
Set g:vimbiosis_enable_virtual_text = 0 to use gutter signs instead: "+" for
additions, "~" for modifications, and "-" for removals. Modified lines then use
VimbiosisChanged (DiffChange), a third highlight color. With Vim's default
signcolumn=auto, the gutter appears only while signs are present.
The default is 1. Unsupported builds also use gutter signs. Notifications
without removal data cannot display the original removed text.

Set these variables in your vimrc to customize the diff characters:
>
    let g:vimbiosis_diff_add_char = 'A'
    let g:vimbiosis_diff_remove_char = 'R'
    let g:vimbiosis_diff_change_char = 'C'
    let g:vimbiosis_diff_padding_char = '.'
<
Each setting accepts one printable character that occupies one display cell.
An unset or invalid setting uses the default. Add, remove, and padding
default to "+", "-", and a space. The default change character matches the
add character in virtual-text mode and is "~" in the gutter.
Padding applies to the inline column on unmarked lines and to the fill at
the end of highlighted virtual rows. Settings take effect on repaint.

Without a snapshot, a file-level list entry is
recorded without highlights. Entirely deleted files remain in the list without
opening an empty file buffer.

Entering Insert mode clears all Vimbiosis highlights, virtual text and signs in that buffer.
Other buffers retain their markers. Change-list entries remain navigable;
clearing markers does not remove them. A later edit replaces the previous
regions for that file. :VbioChangesClear clears both the list and all markers.

:VbioDiff opens or focuses a side-by-side review tab from a file or selected
Vimbiosis location-list row. The left pane holds the pre-edit snapshot and
the right pane is the live file buffer. Use [c and ]c to move between hunks,
do to restore a hunk from the left, and :tabclose to leave the review.
Inline markers return when you leave the review if the buffer has not changed.

:VbioChanges opens a location list of changed regions across files. Select an
entry with Enter or use :VbioNext and :VbioPrevious. Within the associated file
window, the standard :lnext, :lprevious, :lopen and :lclose commands also work.
Each entry includes its file, line, kind of change, and added/deleted counts.
:VbioToggleChanges toggles this specific list from any window. The plugin
installs no default keybindings. For example, add this to your vimrc:
    nnoremap <silent> <leader>c :VbioToggleChanges<CR>

When the list contains changes to multiple files, it opens automatically after
the edit batch finishes, without moving keyboard focus. Its initial height is
at most five rows. An already open list is updated without resetting its size.
Set `let g:vimbiosis_auto_open_changes = 0` in your vimrc to disable automatic
opening. The default is 1. :VbioChanges still opens the list on demand.

Live follow shows the latest edited file and scrolls its owned viewer to the
first changed region. Files visible in the current tab refresh in place. Every
file remains in the change list even when subsequent edits replace the viewer's
contents. :VbioFollow pauses/resumes automatic display of hidden files; visible
buffers still refresh, and the change list still records edits.

Customize VimbiosisAdded, VimbiosisChanged and VimbiosisDeleted highlight groups
to suit your colorscheme. They do not alter the file contents or syntax rules.
Older Vim builds without sign functions retain refresh and change-list support
but omit the highlights and gutter markers.

DIAGNOSTICS                                             *vimbiosis-diagnostics*

Bridge requests are queued by the channel callback and processed by a 50ms
timer, including while Vim is idle in a terminal. The timer stops when the
bridge closes. Editor requests have a five-second bridge deadline; the CLI
waits longer so it can receive and report that timeout rather than racing it.

When refreshing a clean buffer, Vimbiosis temporarily enables that buffer's
'autoread' while switching to it and reloading. Otherwise Vim can wait for an
external-file-change confirmation before the reload command runs. The original
buffer-local setting is restored afterwards; global 'autoread' is unchanged.
Unsaved buffers are still blocked and are never forcibly reloaded.

For an intermittent delay, inspect :echo g:vimbiosis_trace after reproducing.
This bounded in-memory trace contains the last 64 queued/started/replied events
with request IDs, operation names, monotonic timestamps, and Vim modes. It
contains no file paths, buffer contents, or attachment tokens.
